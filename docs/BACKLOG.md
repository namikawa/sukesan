  - 発行と削除が重なっても、削除したキーが復活しない。
  - 同一ラベルの重複発行と件数上限を並行時にも守る。
  - file / Firestore の双方で検証する。

## CQ-02: OAuth更新と解除・再連携の競合

- 対象: `helpers/oauth_helpers.rb`、`routes/admin.rb`、トークンストア、関連spec。
- 問題: refreshはプロバイダ別ロック内で保存するが、解除・OAuth callbackの保存は同じロックを使わない。refresh完了時の保存で解除が取り消されたり、新しい連携情報が上書きされたりする可能性がある。
- 方針: refresh、解除、再連携の保存を既存のプロバイダ別ロックで直列化し、ロック中の再読込と処理順を揃える。
- 実装方針の詳細:
  - Googleの解除は、最新トークンの読出し、revoke、ローカル削除を同じロック内で行う。
  - callbackは認可コードの交換から保存までをロックに含める。Googleではuserinfo取得も含め、解除とトークン交換が重ならないようにする。
  - ストアの `save` / `clear` 自体への自動ロック追加は避け、既存refreshのロックと二重にならないようにする。
  - 監査、通知、リダイレクトはロック外に保ち、GoogleとMicrosoftのロックを分ける。
- 受入れ条件:
  - refreshと解除が重なっても、解除完了後にトークンが復活しない。
  - refreshと再連携が重なっても、新しい連携情報が古いrefresh結果で上書きされない。
  - Google / Microsoft を個別に保護し、プロバイダ間で不要に待たせない。
  - refresh失敗時の扱い、Google revokeのベストエフォート、監査・認可・CSRFを維持する。
  - 既存のfile / Firestoreのロック方式と単一インスタンスの運用前提を維持する。
- 実施内容:
  - `routes/admin.rb` のGoogle / Microsoftのcallbackと解除の4経路を既存のプロバイダ別ロックで保護した。
  - `lib/token_store.rb` と両トークンアダプタに、refresh・再連携・解除が同じロックを使うことを明記した。
  - `spec/requests/oauth_concurrency_spec.rb` と共有テストに、各バックエンド13ケースを追加した。
- 再現結果: 修正前はfile / Firestoreそれぞれ10ケース中9ケースで競合を再現した。プロバイダ間の独立性1ケースは既存実装でも成功した。修正後は失敗時の保存維持とrevokeのタイムアウトも含む13ケースすべてが成功した。
- 分割後の再検証結果（2026-10-15）:
  - 通常RSpec: 577件成功、失敗0件。
  - Firestoreタグ付きRSpec: 52件成功、失敗0件（CQ-01を含む実エミュレータ検証）。
  - RuboCop: 109ファイル、違反なし。
  - Ruby版整合確認: 3.4.11で全箇所一致。
  - `git diff --check`: 成功。
- エミュレータに `sun.misc.Unsafe` とトランザクションのロック待機超過の警告が出たが、タグ付き52件はすべて成功した。
- 維持した前提: Firestoreのトークン排他は同一インスタンス内で行う。解除より後に処理される明示的なcallbackは再連携として扱い、進行中の認可フローを取り消す仕組みは追加していない。

## 検証コマンド

通常のRSpecは実データへのアクセスを拒否するガードを先に読み込んで実行した。

```sh
bundle exec ruby -r ./spec/support/protected_file_guard.rb -S rspec --seed 20261015 --format progress
bundle exec rubocop --cache false
git diff --check
```

Firestoreは専用エミュレータを起動してから、CIと同じタグ指定で実行した。

```sh
FIRESTORE_EMULATOR_HOST=127.0.0.1:8085 FIRESTORE_PROJECT_ID=sukesan-pr-split-20261015 \
  bundle exec ruby -r ./spec/support/protected_file_guard.rb -S rspec --tag firestore --seed 20261015 --format progress
```

外部HTTP通信はWebMockで再現し、保存は一時ファイルまたは実エミュレータを使用した。
